\subsection{Input corpus: scraping and deduplication}
\label{sec:dataset-scraping}

\paragraph{Scraping.}
Source PBTs come from our RealPBT dataset (citation omitted for double-blind review)\footnote{The dataset will be released on HuggingFace upon de-anonymization.}, assembled by a custom Python scraper that operates on the GitHub dependency graph of the Hypothesis library.
The scraper first built the candidate repository list by crawling the GitHub dependency graph of the Hypothesis library~\cite{hypothesis2024dependents} page by page using the PyGitHub API, collecting 19{,}808 unique owner/repository pairs into a static snapshot.\footnote{The dependency-graph crawl was run once offline; the resulting \texttt{dependents.json} snapshot is read by the main scraper at startup.} For each candidate, the scraper iterates asynchronously with rate-limit-aware GitHub REST API backoff, shallow-clones the repository, and uses ripgrep to locate files containing the \texttt{@given} decorator.
For each such file, it parses the Python AST to extract all PBT functions---identified as function definitions whose decorator list includes a call to \texttt{given}---and performs a transitive static call-graph traversal to recover the minimal closure of locally-defined helpers called by each PBT.
Repository metadata (name, URL, license, stars, forks, commit hash) and extracted PBTs (source code, dependency names and their source) are persisted to PostgreSQL; repos whose commit hash was already processed are skipped, enabling incremental re-scraping.
Only repositories whose license matches a permissive allowlist (MIT, Apache-2.0, BSD variants, ISC, Unlicense, CC0, BlueOak-1.0.0) contribute PBTs to the released dataset.

\paragraph{Fork deduplication.}
The raw scrape, run with a 24-hour time budget, yielded 54,345 PBTs, but GitHub's dependency graph surfaces many forks of the same upstream (e.g., hundreds of forks of \texttt{pytorch} each carrying an identical Hypothesis test suite).
We deduplicate by grouping repositories whose names share the same base component, selecting a canonical representative per group (highest star count, breaking ties by PBT count), and retaining PBTs from canonical repos plus any PBTs unique to forks (identified by SHA-256 of whitespace-normalized code).
After fork deduplication the corpus contains 11,039 PBTs across 333 repositories from 281 unique GitHub users.

\subsection{Corpus statistics}
\label{sec:dataset-stats}

Table~\ref{tab:dataset-stats} summarizes the post-deduplication input corpus; the full post-production pipeline that produces the final benchmark from these PBTs is described in \Secr{pipeline}.
The star and fork distributions are heavily right-skewed: the median repository has 0~stars, reflecting that most real-world Hypothesis users work on small or personal projects.
The median PBT is 13 lines with a cyclomatic complexity of 2, consistent with the concise, assertion-focused style typical of Hypothesis tests.
Halstead effort, a measure of the cognitive work required to write the code, has a median of 3 and a long right tail (mean 207, 95th percentile 981), consistent with a corpus dominated by short, simple tests alongside a minority of complex multi-strategy properties.

Figure~\ref{fig:realpbt_pbt_vs_deps} characterizes the relationship between PBT complexity and the complexity of the code each PBT tests.
On average, PBTs are concise (median 18 LOC) while their direct local dependencies total roughly 30× more code (mean 553 dep LOC).
The ratio is right-skewed: many PBTs exercise a handful of short helper functions, but a substantial tail tests deeply nested call graphs spanning hundreds of lines.
Notably, PBT complexity is nearly independent of dependency complexity (Pearson $r = 0.06$ between test cyclomatic complexity and dependency count), confirming that Hypothesis encourages engineers to write simple, focused tests regardless of how complex the underlying code is.

\paragraph{Comparison with the Hypothesis Corpus.}
DeVoe~\cite{devoe2026hypothesis} recently released the Hypothesis Corpus 2026 (HC-2026): 28,928 Hypothesis tests from 1,504 repositories, assembled by the Hypothesis development team to study PBT \emph{runtime behaviour}---how generators consume entropy, how tests are distributed in time, which predicates fire.
We built RealPBT for a different purpose: supplying clean, license-clear, dependency-annotated PBTs for Lean formalization.
These divergent goals drive the key design differences summarised in Table~\ref{tab:dataset-comparison}: HC-2026 is richer in runtime context (timing, coverage, entropy), while RealPBT provides what formal verification requires (dependency source, static metrics, NL summaries) with a stricter license filter.
Table~\ref{tab:dataset-comparison} also shows the repository overlap we computed programmatically: 28 exact matches after their validity filter, 111 (33\%) before it.
A full methodological comparison is given in \Secr{related}.
