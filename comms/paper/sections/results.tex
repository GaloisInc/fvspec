\section{Results}
\Secl{results}

We present a characterization of the \FVSpec benchmark along six axes: dataset scale, source code properties, translation quality, output complexity, pipeline cost, and difficulty stratification. All quantitative claims in this section correspond to programmatically generated figures; we report the dataset-level statistics from the public HuggingFace release and direct the reader to the accompanying visualizations for distributional detail.

\subsection{Dataset Scale}

The released dataset contains 9,415 Lean 4 formalization challenges derived from 2,772 unique Python property-based tests. Two pipeline runs contribute to the dataset: an initial run (\texttt{feb03}, 5,979 samples, Claude Sonnet) and a second run (\texttt{apr08}, 3,436 samples, Claude Sonnet 4.6). Because the same PBT may be formalized in multiple ways across runs, each unique PBT has between 1 and 15 formalizations. Sixty-five percent of multi-formalization groups exhibit a Pareto front larger than one: no single formalization dominates on all structural faithfulness sub-metrics simultaneously, confirming that the multiple-formalization design captures genuinely complementary aspects of each PBT.

\subsection{Python Source Characteristics}

Figure~\ref{fig:python_source} characterizes the input PBTs along three axes: lines of PBT code, average cyclomatic complexity (Radon), and maintainability index. The source tests span a wide range of complexity, from trivial single-assertion tests to multi-strategy tests exercising complex library APIs. This diversity is inherited directly from real-world engineering practice and is not curated or filtered for difficulty.

\subsection{Translation Quality}

We evaluate translation quality using \emph{structural faithfulness}, a composite metric that decomposes into five sub-scores: parameter coverage, type correspondence, strategy coverage, assertion coverage, and dependency coverage (described in the preceding section). Figure~\ref{fig:structural_faithfulness} shows the distribution of the overall score and the mean of each sub-score across the dataset. The overall faithfulness distribution exhibits a clear mode above 0.5, indicating that the majority of translations preserve the essential structure of the source PBT, though a long tail of lower-quality translations remains.

\begin{figure}[t]
  \centering
  \includegraphics[width=\linewidth]{figs/structural_faithfulness.png}
  \caption{Structural faithfulness: distribution of the overall composite score (left) and mean sub-scores (right).}
  \label{fig:structural_faithfulness}
\end{figure}

Of the 9{,}415 samples, 59\% reached a provided implementation level (full Lean code generated by the agent); the remaining 41\% fell back to signature-only stubs. Structural faithfulness is comparable across both levels (mean 0.67 vs.\ 0.68), suggesting specification quality is largely independent of implementation completeness.

\subsection{Lean Output Complexity}

Figure~\ref{fig:lean_complexity} characterizes the generated Lean artifacts: total lines of Lean code, number of theorems per sample, and number of \texttt{sorry} placeholders. The median sample contains multiple theorems, each requiring an independent proof. The \texttt{sorry} count tracks the theorem count closely, as expected from our pipeline design (each theorem is emitted with a \texttt{sorry} placeholder).

\subsection{Pipeline Cost}

Figure~\ref{fig:pipeline_cost} reports the per-sample pipeline cost in three dimensions: wall-clock time, token usage, and number of agent turns. The distributions are right-skewed, reflecting the iterative repair loop: most samples compile within a few turns, but a tail of difficult translations requires many repair iterations before the Lean LSP reports success or the budget is exhausted.

\subsection{Difficulty Stratification}

Each sample is graded for proof difficulty by Claude Haiku 4.5, which assigns a binary label (\emph{easy} or \emph{hard}) along with a confidence score. Figure~\ref{fig:difficulty_distribution} shows the resulting split and the distribution of grader confidence. The benchmark contains a substantial proportion of both easy and hard problems, and the grader expresses high confidence for the majority of assessments.

\begin{figure}[t]
  \centering
  \includegraphics[width=\linewidth]{figs/difficulty_distribution.png}
  \caption{Difficulty distribution: easy vs.\ hard counts (left) and grader confidence distribution (right). $n$ shown in title.}
  \label{fig:difficulty_distribution}
\end{figure}

Figure~\ref{fig:difficulty_vs_faithfulness} examines the relationship between difficulty and two output characteristics: structural faithfulness and Lean output size. Hard problems tend to produce longer Lean outputs, consistent with the intuition that more complex source PBTs lead to more elaborate formalizations and more challenging proofs.
